Do GitHub ao SharePoint

O caminho completo para tirar a ferramenta da sua máquina e colocá-la no ar, funcionando com o Microsoft 365 da GS2. São oito etapas, cerca de 2 horas no total, e nenhuma delas exige saber programar — o que exige é ter, na hora certa, permissão de administrador no Microsoft 365 e acesso ao DNS de gs2negocios.com.br.

Antes de começar

Cinco coisas que, se faltarem no meio do caminho, travam tudo.

  • Conta do Azure com um cartão cadastrado. O custo real fica em torno de R$ 30 a R$ 60 por mês.
  • Permissão de administrador global no Microsoft 365 da GS2 — é o que permite conceder consentimento na etapa 2.
  • Acesso ao DNS de gs2negocios.com.br, onde os registros do domínio são editados.
  • Conta no GitHub e o Git instalado no Mac (ele já vem; confirme com git --version).
  • A pasta da ferramenta em Ferramentas/Societário, rodando na sua máquina.
◆ Não precisa fazer tudo de uma vez. As etapas 1 a 3 são independentes e podem ser feitas hoje. Da 4 em diante uma depende da anterior. A etapa 7 tem espera de DNS, que pode levar horas — comece por ela cedo no dia se quiser terminar no mesmo dia.
1

Subir o código para o GitHub

O código sai da sua máquina e passa a ter histórico, com quem mudou o quê.

Mac + GitHub15 min

  1. Em github.com/new, crie o repositório com o nome gs2-processos-societarios.

    Marque Private. Deixe desmarcadas as opções de README, .gitignore e licença — o repositório já tem os seus.

  2. Abra o Terminal e rode, uma linha por vez:

    # entra na pasta da ferramenta
cd ~/Desktop/Ferramentas/Societário

# prepara o repositório e faz o primeiro registro
git init
git add .
git commit -m "Ferramenta de processos societários — versão inicial"

# liga na sua conta do GitHub e envia
git branch -M main
git remote add origin https://github.com/SUA-CONTA/gs2-processos-societarios.git
git push -u origin main

    Troque SUA-CONTA pelo seu usuário do GitHub. Se ele pedir senha, não é a do site: crie um token em Settings › Developer settings › Personal access tokens e cole no lugar da senha.

  3. Recarregue a página do repositório no navegador. Os arquivos devem estar lá.

✓

Como saber que deu certo

O GitHub mostra a pasta web/, a pasta api/ e o arquivo README.md na tela inicial do repositório. Se aparecer a pasta node_modules, algo saiu errado no .gitignore — me avise antes de seguir.

■ Confirme que o repositório é privado. Ele contém nomes reais de clientes da GS2 nos dados de exemplo. Um repositório público exporia isso a qualquer pessoa na internet.
2

Registrar a ferramenta no Microsoft Entra ID

É aqui que a Microsoft passa a reconhecer a ferramenta e a deixá-la conversar com o SharePoint.

portal.azure.com25 min

Esta é a etapa mais longa e a que mais dá errado — não porque seja difícil, mas porque tem um passo que quase todo mundo esquece (o número 5). Faça na ordem.

  1. No portal.azure.com, busque por Microsoft Entra ID e vá em Registros de aplicativo › Novo registro.

  2. Nome: GS2 — Processos Societários.

    Tipos de conta suportados: Apenas contas neste diretório organizacional.

    URI de Redirecionamento: escolha a plataforma Aplicativo de página única (SPA) e digite https://app.gs2negocios.com.br/auth.html. Clique em Registrar.

  3. Ainda em Autenticação, clique em Adicionar URI e acrescente também http://localhost:5173/auth.html — é o que permite testar na sua máquina.

  4. Vá em Permissões de API › Adicionar uma permissão › Microsoft Graph › Permissões delegadas. Marque User.Read e Sites.ReadWrite.All.

    Depois clique em Conceder consentimento do administrador para GS2. As duas linhas devem ficar com um visto verde.

  5. O passo esquecido. Vá em Expor uma API:

    — clique em Adicionar ao lado do URI do aplicativo e aceite o valor sugerido (api://…);

    — clique em Adicionar um escopo, nomeie access_as_user, marque Administradores e usuários, preencha os textos de consentimento com algo como “Acessar os processos societários” e salve;

    — volte em Permissões de API › Adicionar uma permissão › Minhas APIs › escolha o próprio GS2 — Processos Societários › marque access_as_user › adicione e conceda o consentimento de novo.

  6. Volte em Visão geral e anote os dois códigos. Você vai usá-los nas etapas 5 e 6:

    ID do aplicativo (cliente)  →  usado como clientId
ID do diretório (locatário) →  usado como tenantId
✓

Como saber que deu certo

Na tela Permissões de API devem aparecer três linhas, todas com “Concedido para GS2” em verde: User.Read, Sites.ReadWrite.All e access_as_user. Se forem só duas, o passo 5 não foi concluído.

◆ Por que o passo 5 existe. As duas primeiras permissões deixam a ferramenta falar com o SharePoint. A terceira deixa a ferramenta falar com o próprio backend dela, que guarda os processos. Sem ela, você consegue entrar, mas o painel aparece vazio e o diagnóstico acusa erro 401.
3

Criar o banco de dados

É onde os processos passam a viver — o que hoje some quando você fecha o navegador.

portal.azure.com10 min

  1. Criar um recurso › busque Azure Cosmos DB › Criar › escolha Azure Cosmos DB for NoSQL.

  2. Tipo de capacidade: Sem servidor (Serverless). É o que faz você pagar por uso em vez de uma mensalidade fixa.

    Região: Brazil South. Nome da conta: algo como gs2-processos.

  3. Crie e espere terminar (uns 5 minutos). Não crie banco nem contêiner à mão — a ferramenta cria sozinha na primeira vez que rodar.

    Ela cria o banco gs2processos com cinco contêineres: processos (o estado de cada processo), cadastros (usuários, requerentes, pessoas, modelos), auditoria (a trilha), acervo (o retrato do que está arquivado no SharePoint) e replica (a etapa 2, ainda desligada).

  4. Quando terminar, entre no recurso, vá em Chaves e deixe anotados o URI e a CHAVE PRIMÁRIA. Você usa na etapa 5.

✓

Como saber que deu certo

O recurso aparece com status Online e a tela Chaves mostra o URI no formato https://gs2-processos.documents.azure.com:443/.

◆ Sobre a chave. Usar a chave da conta é o caminho mais rápido para começar, e é o que este manual segue. Existe um caminho melhor — dar identidade própria ao aplicativo, sem senha nenhuma guardada — que vale fazer depois, com calma. Está descrito em docs/implantacao.md, no repositório.
4

Criar a publicação, ligada ao GitHub

A partir daqui, todo envio de código para o GitHub publica sozinho.

portal.azure.com15 min

  1. Criar um recurso › busque Aplicativo Web Estático (Static Web App) › Criar.

  2. Nome: gs2-processos. Plano: Gratuito — ele já inclui o backend e atende de sobra.

  3. Em Detalhes da implantação, escolha GitHub, autorize o Azure e selecione a sua organização, o repositório gs2-processos-societarios e o branch main.

  4. Em Detalhes de build, escolha o predefinido Personalizado e preencha exatamente assim:

    Local do aplicativo   web
Local da API          api
Local de saída        (deixe vazio)

    Esses três campos dizem ao Azure onde está a ferramenta e onde está o backend. Errar aqui é a causa mais comum de “publicou mas a página não abre”.

  5. Crie. O Azure escreve sozinho um arquivo de automação no seu repositório e dispara a primeira publicação.

  6. No GitHub, abra a aba Actions e acompanhe. A primeira leva de 2 a 4 minutos e termina com um visto verde.

✓

Como saber que deu certo

Na Visão geral do Static Web App há um endereço terminado em .azurestaticapps.net. Abra: a tela de login da ferramenta aparece, com a foto e a frase da marca. Ela ainda vai dizer modo demonstração — é o esperado, resolve na etapa 6.

5

Configurar o backend

Aqui o backend descobre quem valida os logins e onde fica o banco.

portal.azure.com10 min

  1. No Static Web App, vá em Configuração › Configurações do aplicativo.

  2. Adicione uma por uma, com + Adicionar:

NomeValorDe onde vem
GS2_TENANT_ID · obrigatóriao ID do diretórioetapa 2, passo 6
GS2_CLIENT_ID · obrigatóriao ID do aplicativoetapa 2, passo 6
GS2_BANCO · obrigatóriacosmosfixo — escrito exatamente assim, em minúsculas
COSMOS_ENDPOINT · obrigatóriao URI do Cosmosetapa 3, passo 4
GS2_ADMINSvinicius@gs2negocios.com.brquem entra como administrador; separe por vírgula para incluir outros
COSMOS_KEYa chave primáriaetapa 3, passo 4
COSMOS_DBgs2processosfixo
GS2_RETENCAO_DIAS0prazo de guarda de dado pessoal; 0 = sem prazo definido

Ao terminar, clique em Salvar no topo. O backend reinicia sozinho em poucos segundos.

✓

Como saber que deu certo

Abra SEU-ENDEREÇO.azurestaticapps.net/api/saude no navegador. Precisa vir "modo":"entra" e "bancoOk":true.

Se vier "modo":"mal-configurada", falta GS2_TENANT_ID ou GS2_CLIENT_ID — e, nesse estado, o backend não autentica ninguém, de propósito. Se vier "modo":"local", alguém criou a variável GS2_PERMITIR_DEMO lá: apague agora, antes de qualquer outra coisa. Se vier "bancoOk":false, o campo bancoErro na mesma resposta diz o que falta — GS2_BANCO, COSMOS_ENDPOINT, ou a permissão no Cosmos. Nesse estado todas as outras rotas respondem 503 até você corrigir.

Essa resposta é enxuta de propósito: o endereço do banco, a contagem de registros e o estado da réplica só aparecem para quem entra como administrador. Antes eles ficavam visíveis para qualquer um na internet.

■ A chave do Cosmos é segredo. Ela vive só aqui, nas configurações do Azure. Nunca coloque num arquivo do repositório — quem tem essa chave lê e escreve todo o banco.
■ Nunca crie a variável GS2_PERMITIR_DEMO no Azure. Ela existe só para o servidor de teste da sua máquina, que escuta apenas em 127.0.0.1. No Azure, ela faz o backend voltar a aceitar identidade declarada por cabeçalho — qualquer pessoa na internet passaria a ler todos os processos e todos os CPFs, sem senha nenhuma, e /api/saude ainda anunciaria essa condição.
◆ Por que quatro variáveis são obrigatórias agora. Até setembro de 2026 o backend “se virava” quando faltava alguma: sem os IDs do Entra ele caía em modo demonstração; sem o Cosmos, gravava num disco temporário que some a cada reinício. Nos dois casos parecia funcionar. Depois da auditoria de segurança, ele passou a recusar as duas coisas — errar uma variável agora derruba o backend, e é assim que tem de ser. Prefira o erro barulhento à ferramenta publicada aberta.
6

Ligar o login de verdade

O momento em que a ferramenta sai do modo demonstração.

Mac + GitHub10 min

  1. Na sua pasta, abra web/config.js em qualquer editor de texto.

  2. Preencha as duas linhas vazias com os códigos da etapa 2 e salve:

    window.GS2_CONFIG_OVERRIDE = {
  tenantId: 'cole aqui o ID do diretório',
  clientId: 'cole aqui o ID do aplicativo',
  clientesViaEntra: false,   // true quando for liberar acesso a clientes
  ...
};

    clientesViaEntra decide como o cliente externo entra. Com false, a aba Cliente fica bloqueada e explica isso na tela — é o certo enquanto você não for liberar acesso externo. Com true, o cliente entra pela janela da Microsoft, como a equipe. Não existe mais o meio-termo: até setembro de 2026, com false em produção, bastava conhecer o e-mail de um cliente cadastrado para entrar como ele.

  3. Envie a mudança:

    cd ~/Desktop/Ferramentas/Societário
git add web/config.js
git commit -m "Configura o Entra ID de produção"
git push

  4. Acompanhe no GitHub, aba Actions. Em 2 a 4 minutos está publicado.

✓

Como saber que deu certo

Abra a ferramenta e recarregue. O aviso amarelo de modo demonstração na tela de login some. Ao entrar com vinicius@gs2negocios.com.br, abre a janela de login da Microsoft — é ela que passa a autenticar.

◆ Esses dois códigos não são segredo. Eles ficam visíveis para qualquer pessoa que abrir a ferramenta, e é assim mesmo — servem para identificar o aplicativo, não para dar acesso. Por isso vão no repositório: é o que torna a publicação repetível.
7

Apontar o endereço da GS2

Trocar o endereço automático do Azure por app.gs2negocios.com.br.

Azure + DNS20 min + espera

  1. No Static Web App, vá em Domínios personalizados › Adicionar › Domínio personalizado no outro DNS.

    Digite app.gs2negocios.com.br. O Azure mostra um valor de CNAME — deixe a tela aberta.

  2. No painel onde o domínio gs2negocios.com.br é administrado, crie um registro:

    Tipo   CNAME
Nome   app
Valor  o endereço .azurestaticapps.net que o Azure mostrou
TTL    3600

  3. Volte ao Azure e clique em Validar. Se reclamar, espere: a propagação de DNS costuma levar de 15 minutos a algumas horas. Pode fechar e voltar depois.

  4. Validado, o certificado de segurança é emitido sozinho em alguns minutos — o cadeado aparece no navegador sem você fazer nada.

  5. Não esqueça deste: volte ao Entra ID › Autenticação e confirme que https://app.gs2negocios.com.br/auth.html está na lista de URIs. Sem isso, o login recusa no endereço novo.

✓

Como saber que deu certo

app.gs2negocios.com.br/login abre a ferramenta com cadeado no navegador, e o login com a conta da GS2 funciona.

◆ O site institucional não é tocado. Estamos criando um endereço novo (app.), não mexendo em gs2negocios.com.br. Se quiser que gs2negocios.com.br/login leve à ferramenta, isso é um redirecionamento simples no site atual, feito depois.
8

Conferir a integração e começar a usar

Provar que grava mesmo no SharePoint, e trazer os processos que já estão em andamento.

Na ferramenta20 min

  1. Entre como vinicius@gs2negocios.com.br. No canto superior direito, clique no selo de ambiente — ele abre o Diagnóstico da integração.

  2. O diagnóstico roda as mesmas chamadas do dia a dia e mostra uma a uma. Todas devem ficar verdes até “Pastas de cliente lidas”, com uma contagem que bate com o SharePoint.

    Se alguma falhar, ela diz exatamente o quê — inclusive qual endereço precisa estar registrado no Entra ID, que é o erro mais comum.

  3. Clique em Executar teste de gravação e confirme. Isso cria de verdade uma pasta Z - Testes da Ferramenta no SharePoint, envia um arquivo e lê de volta.

    Abra o SharePoint e veja a pasta lá. É esta a prova de que a integração funciona. Depois apague a pasta — a ferramenta nunca apaga nada sozinha.

  4. O Painel abre com zero processos, e é assim mesmo: a ferramenta não traz exemplo nenhum embutido — nenhum processo, cliente ou requerente vem no código. Só o seu usuário administrador já está cadastrado. Os passos seguintes é que a enchem.

  5. Vá em Administração › Acervo do SharePoint e clique em Varrer todos os clientes. É este passo que enche o Painel de Clientes com dado real — sem ele a ferramenta abre sabendo apenas os nomes das pastas.

    Ela percorre, cliente por cliente, 03 - Societario › 03.01 - Contratos Sociais, CNPJ e QSA, lê os nomes dos arquivos (tipo do ato, número da alteração, data, razão social) e abre só dois documentos por cliente — o Cartão CNPJ e o QSA mais recentes — para tirar deles CNPJ, endereço, natureza jurídica, CNAE e quadro societário. Contrato social não é aberto: é texto corrido, e leitura automática ali erra mais do que acerta.

    De 40 a 60 clientes leva alguns minutos, e dá para parar no meio — o que já foi lido continua na tela. Quando terminar, confira a tabela e só então clique em Gravar no banco. Ela só lê o SharePoint, com a sua permissão, e não grava nada lá.

  6. Vá em Administração › Importar processos, baixe a planilha modelo, preencha uma linha por processo em andamento e solte de volta na tela.

    Ela confere linha por linha e mostra o que está certo e o que tem problema antes de gravar. Só cliente e tipo são obrigatórios.

  7. Cadastre a equipe em Administração › Usuários e avise que o acesso está no ar.

✓

Como saber que deu certo

Você cria um processo, fecha o navegador, abre de novo e ele continua lá. Um colega entra com o e-mail dele e vê o mesmo painel. O arquivo de teste apareceu no SharePoint. E o Painel de Clientes mostra as empresas com CNPJ, sócios e histórico de alterações vindos do acervo — não mais em branco.

Depois que estiver no ar

Como as mudanças passam a acontecer.

Você não vai mais rodar comando de publicação. O ciclo passa a ser sempre o mesmo, e o ponto importante é que você vê a mudança funcionando antes de ela chegar em produção: cada proposta de alteração ganha um endereço temporário próprio no Azure, com a ferramenta rodando de verdade.

Alteração num branch→ Pull Request→ Endereço de pré-visualização→ Você testa→ Merge→ No ar

Para pedir uma mudança, é só me chamar com a pasta conectada — eu edito, você lê o que mudou e envia. O arquivo CLAUDE.md na raiz do repositório guarda as decisões de arquitetura e as regras da marca, e é lido automaticamente pelas sessões futuras, para que ninguém desfaça sem querer o que já foi decidido.

Antes de cada envio, rode a bateria de testes. São quatro arquivos, sem instalar nada além do Node, e levam cerca de meio minuto: 

cd ~/Desktop/Ferramentas/Societário
node testes/interpretador-de-nomes.js   # 28 nomes reais da sua biblioteca
node testes/montagem-da-ficha.js        # ficha, histórico, Cartão CNPJ, QSA
node testes/seguranca-da-api.js         # 36 verificações de permissão e acesso
node testes/estresse.js                 # volume e entradas malformadas

São 84 verificações ao todo. O seguranca-da-api.js não é exercício teórico: ele sobe o backend numa porta própria e tenta, uma a uma, as coisas que não podem funcionar — entrar sem senha, ler o processo de outro cliente, apagar um cadastro pelo identificador errado, ler um arquivo de fora da pasta pública. Cada linha dele corresponde a uma falha que já existiu e foi corrigida em setembro de 2026. Se algum falhar, não envie — me chame.

A etapa 2 do projeto já está escrita e desligada: a réplica que confere sozinha se o que a ferramenta diz bate com o que está no SharePoint, e que destrava alertas de prazo da Junta. Ligar é dar identidade própria ao backend e virar uma chave — o passo a passo está em docs/implantacao.md, no repositório.

Quando alguma coisa não funcionar

Os tropeços conhecidos e o que cada um significa.

O que você vêO que é, e como resolver
A ferramenta abre em modo demonstração mesmo publicadaO web/config.js subiu sem tenantId e clientId, ou o envio ainda não terminou. Confira na aba Actions do GitHub se a última publicação ficou verde.
AADSTS50011 — erro de redirecionamentoO endereço que a ferramenta usa não está registrado no Entra ID. O diagnóstico mostra o endereço exato — copie e cole, sem alterar nada, inclusive o https.
Entra, mas o painel fica vazio e o diagnóstico acusa 401Faltou o passo 5 da etapa 2 — o escopo access_as_user ou o consentimento dele.
A janela de login abre e fecha sozinhaBloqueador de pop-up do navegador. Libere o endereço da ferramenta.
Graph 403 ao listar as pastasFalta o consentimento de administrador em Sites.ReadWrite.All, ou a conta usada não tem acesso ao site /sites/clientes no SharePoint.
Graph 404 no siteO endereço do SharePoint está errado no config.js. O correto é gs2negociosmt.sharepoint.com com o caminho /sites/clientes.
O selo do topo diz “sem banco”O backend não respondeu. Abra /api/saude no navegador e confira as variáveis da etapa 5.
/api/saude responde "modo":"local"Trate como urgente. Existe uma variável GS2_PERMITIR_DEMO nas configurações do Azure. Nesse estado o backend aceita identidade declarada, sem senha. Apague a variável, salve, e confira de novo.
/api/saude responde "modo":"mal-configurada"Falta GS2_TENANT_ID ou GS2_CLIENT_ID. O backend não autentica ninguém assim — é a proteção funcionando, não um defeito.
Tudo responde 503 e /api/saude traz "bancoOk":falseLeia o bancoErro na mesma resposta: falta GS2_BANCO=cosmos, COSMOS_ENDPOINT, ou a identidade não recebeu a função no Cosmos. Antes ele caía num banco temporário e os dados sumiam calados; agora ele para e avisa.
A aba Cliente diz que o acesso não foi habilitadoÉ o esperado com clientesViaEntra: false e o Entra ligado. Mude para true no config.js quando for liberar acesso externo.
A varredura do acervo lê o histórico, mas nenhum CNPJO leitor de PDF não carregou — normalmente porque a rede do escritório bloqueia cdnjs.cloudflare.com. A linha do tempo continua saindo dos nomes de arquivo; o CNPJ e os sócios, não.
Uma tela some ou um botão não faz nada só em produçãoProvável bloqueio da política de segurança (CSP) do staticwebapp.config.json. Abra o console do navegador: chamada bloqueada por CSP não mostra erro na tela. Se um serviço externo novo foi acrescentado, ele precisa entrar na CSP.
“Falha na API. Código para o suporte: xxxx”É o comportamento certo: a mensagem técnica não vai mais para a tela (ela entregava o endereço do banco). Procure esse código no log da Function para ver o detalhe.
A lista de clientes vem vaziaA ferramenta lê as pastas da raiz da biblioteca, ignorando pastas de uma letra só e as que começam com Z -. Se a organização das pastas mudou, me avise para ajustar.
◆ O diagnóstico é sempre o primeiro lugar a olhar. Ele roda as chamadas reais e diz qual delas falhou e por quê — em vez de você adivinhar entre o Entra ID, o Azure e o SharePoint.

Os nomes que aparecem no caminho

Traduzidos para o que significam neste projeto.

GitHub
Onde o código fica guardado, com histórico de quem mudou o quê e quando.
Repositório
A pasta do projeto dentro do GitHub.
Commit e push
Registrar uma alteração e enviá-la para o GitHub.
Microsoft Entra ID
O antigo Azure AD: o sistema que guarda as contas do Microsoft 365 da GS2 e valida os logins.
Static Web App
O serviço do Azure que hospeda a ferramenta e o backend juntos, no mesmo endereço.
Cosmos DB
O banco de dados onde os processos ficam guardados.
Microsoft Graph
A porta oficial da Microsoft pela qual a ferramenta lê e grava no SharePoint.
CNAME
O registro de DNS que faz app.gs2negocios.com.br apontar para o Azure.
Pull Request
Uma proposta de mudança, com o que mudou visível lado a lado, antes de virar realidade.
Permissão delegada
A ferramenta age em nome de quem está logado — quem não enxerga uma pasta no SharePoint também não enxerga por aqui.
